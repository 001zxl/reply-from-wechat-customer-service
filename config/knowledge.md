# 网点实际处理口径与话术

> **来源**：某个申通商家对接群，整天实测（09:35 建群 → 21:31），
> 341 条文字 + 25 张图，全量语料在 `data/history/<群名>.txt`（本地，未进仓库）。
> **我方账号 = 群里那个「商家服务…-查件请@我」客服号**（用户已确认），全天 113 条。
> 这一段是抄自真实对话的口径，不是编的；但"实际这么说过"不等于负责人认可，请过一眼。

## 一、★ 回什么由「这票现在的轨迹状态」决定，不由商家怎么措辞决定

同一个 `+拦截`，我方全天有**六种**不同回法，区别只在这票当时是什么状态。
这条是整个群里最重要的规律：

| 轨迹状态 | 我方标准回复（原话） |
|---|---|
| 查不到轨迹 | `@对方 <单号> 已登记退回（物流轨迹为空），退回请求发送成功` |
| 在途、未派件 | `@对方 <单号> 已登记退回，拦截请求发送成功` |
| 已经是退回件 | `@对方 <单号> 已是退回件，无需重复登记` |
| 已在代收点 / 派件中 | `@对方 <单号>当前在代收点，我司已通知网点退回，务必通知收件人拒收。派件之后的包裹拦截有风险，未有退回物流前麻烦不要给收件人退款，避免造成损失。` |
| 已派件、未签收 | `@对方 <单号> 已登记退回，包裹已派件，已通知站点核实处理，因派件之后的包裹拦截有风险，待有退回记录再退款` |
| 已签收 | `@对方 <单号> 已登记退回，包裹已签收，已通知站点核实处理，因签收之后的包裹拦截有风险，待有退回记录再退款` |
| 已退回并签收 | `@对方 <单号> 已登记退回，包裹已退回并签收，签收网点<到件网点>公司` |

其余固定口径：

| 情形 | 回复 |
|---|---|
| 查件 / 售后 | `@对方 <单号> 已登记查件，客服稍后处理` |
| 撤销拦截 | `@对方 <单号> 已登记取消退回，客服稍后处理` |
| 催揽收 | `@对方 <单号> 包裹还未揽件，已催促小件员尽快取件` |
| 查不到归属网点 | `@对方 该群未绑定 <单号> 单号对应的发货网点【订单网点：<项目名>（<编码>）】，请联系人工客服处理` |

**⇒ 对 AI 的硬要求：先 `query_logistics` 拿到真实状态，再照上表选口径。
绝不允许不查就照商家措辞套话术 —— 每一条口径都对应一个真实状态，套错就是编造。**

## 二、工作流：系统先自动 ack，人工只处理例外

我方 113 条里 **81 条（72%）没有署名**（自助/系统确认），
**32 条（28%）带 `（本条消息为人工客服出港X-XX姓名回复）`**。
人工只出现在下面这几类 —— **这就是 AI 该 handoff 的边界**：

| 必须人工的情形 | 原话 |
|---|---|
| 要派件网点核实 | `此件已反馈派件网点核实处理，后续我司跟进。` |
| 已通知派件网点 | `此件已通知派件网点，我司后续跟进` |
| 破损/理赔，要凭证 | `此件麻烦提供带单号的内件商品价值凭证，和内件商品大图，我司核实，谢谢。` |
| 已签收、拦不住 | `此件收件人已签收，我司无法拦截退回，麻烦自行与收件人处理售后，后续有问题及时反馈，我司完结` |
| 前台签收、联系不上收件人 | `快件已由【前台】签收，我司无法电联收件人，麻烦商家核实是否与收件人售后，若已售后请提供售后凭证，后续有其他问题请及时反馈，我司完结，谢谢` |
| 退回物流还没出 | `还未有退回物流，等等吧。` / `暂缓` |
| 对方前后矛盾 | `此件不是反馈完结了吗？还需要做什么吗？` |

## 三、商户侧：他们怎么说话（识别用）

群里 98 个成员，实际只有 4 类发言者：

**a) ERP 机器人（群里几个自动发单的机器人号）—— 格式极固定**
```
<单号>+拦截
261002-<单号>,<单号>，用户不要了，催退回
```

**b) 售后客服（电商售后-×××（多个人，昵称带"电商售后-xxx"））——「单号＋动词」**
```
<单号> 拦截                 <单号>驿站签收 联系退回
<单号>派件中，联系退回        <单号> 驿站代签不要了，联系退回
<单号>拒收退回              <单号> 能售后吗
<单号> 完结                 <单号>不需要了，完结就行
<单号>没收到联系不到快递员    <单号> 查重
<单号> 催揽收               +260922-…+<单号> 取消 拦截
```
**他们几乎不说完整句子。AI 不能因为对方只丢一个单号就不理，也不能反问"请问办什么业务"。**

**c) ERP 甩整单 —— 最容易读错的一种**
```
<店铺名> +261003-<单号>+<单号>+王昶凯 <单号>
河北省沧州市黄骅市 黄骅港勤诚家园三号楼＋拦截
<店铺名> <单号> <单号>+刘*，1*** ，内蒙古…＋拦截
```
格式是 `店铺名 +[店铺订单前缀]-<订单号>+<运单号>+收件人 姓名 电话 地址 ＋诉求`。
**开头 `261003-…` / `6930175…` 是店铺订单号，不是运单号；
只有后面那串 15 位（777…/770…/773… 开头）才是运单号。查件只查 15 位那串。**

**d) 出港侧问题件通报 —— 带 24 小时时限，是要我们回的**
```
<出港问题件号>（回复@我） <单号>==<店铺名>==此件网点反馈客户拒收，
麻烦告知该包裹是否退回，我司先暂放处理，24h到期退回==扫描类型【拒收】，
原因【客户拒收】，描述【客户不需要/重复购买拒收】麻烦24h内回复我，回复请@我，请知悉
```

**商户侧噪音（我方全天一条都没回过，AI 也不该回）**：
`1`、`11`、`1-`、`--`、`=`、`已揽===`、`gee`、`11.`。

## 四、⚠ 三条不能照抄的

1. **`退回请求发送成功` / `拦截请求发送成功` 是申通内部系统回给网点的回执，网点只是转述。**
   AI 在自己没真拿到系统回执之前**绝对不能这么说** —— 这正是提示词禁止的
   "已经拦截了 / 已经登记了"。
2. **`（本条消息为人工客服出港<工号><姓名>回复）`是署名。** 工号形如
   `1-5` / `1-12` / `1-18` / `1-19` / `1-20`（出港客服组）。
   **AI 不可以套这句** —— 冒充具体职工是造假，还会让人误以为这条经过人工。
3. **`已通知网点退回` / `我司后续跟进` 是网点承诺动作。** AI 只有在真的
   `register_case` 登记成功、或真的查到对应状态时才能说，否则要改成
   "需要网点核实" + 转人工。

## 五、值得学的两个"人的做法"

- **重复登记会被点出来，而且不重复办**：商家同一票反复发拦截时回
  `已是退回件，无需重复登记`。AI 也应该先查再答，不是来一次登记一次。
- **口径对不上时敢反问**：出现过 `@对方 <单号> 此件不是反馈完结了吗？
  还需要做什么吗？` —— 对方前后矛盾时直接点出来问清楚，而不是硬着头皮办。

## 方言 / 当地说法对照（选填，但很有用）

语音是机器转写的，带口音就容易转错。把你们那边常听到的说法写上，
AI 理解语音时会**优先按这张表**。

例（把左边的换成你们当地的说法）：

| 客户可能这么说（语音转写出来的） | 实际意思 |
|---|---|
| 到哪哈了 / 到哪了哈 | 这票到哪了 |
| 推回来 / 腿回去 | 退回 |
| 该地方 / 改地儿 | 改址 |
| 多处钱 / 咋收费 | 问运费 |
| 收了没 / 到没到 | 签收确认 |
| 破了 / 烂了 | 破损 |
| 找不着了 / 没影了 | 丢件 |

行业黑话也写这里，比如某个客户对"大货""小包""电商件"的特殊叫法。
